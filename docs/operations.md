# 运行、恢复与信任边界

## 运行模式

一个站点运行一个活跃 Hub 进程。同一个数据库由这一实例调度。SQLite WAL 持久化节点、快捷指令、浏览器会话、任务、事件、审批和通知发件箱。Hub 可在原数据库上重启，已提交任务按 Sidecar 序号续收，未获派单确认的任务以同一 ID 重试。Sidecar 先把请求摘要与任务 ID 写入节点本地 SQLite，再执行任务。Sidecar 意外退出后，重启将中断的任务标为失败，悬而未决的审批按拒绝处理。同 ID 的原请求可读取已保存结果，内容冲突返回 409。操作员可检查工作目录后决定是否派发新任务。系统服务按失败重启。整台宿主离线时需要在备用主机恢复 Hub 配置、密钥和数据库。

对运行中的 SQLite 使用 SQLite backup API 获取一致快照，或停服后备份数据库与 WAL 文件。节点密钥和任务正文保存在数据库中，备份沿用与私有配置相同的访问权限。恢复时先停旧实例，启动新实例并验证数据库、节点 URL、证书及各 Sidecar 的 Hub 回查地址。任务在共享 NAS 上修改同一个文件时，应由操作者安排顺序。

Hub 的 `GET /health` 在校验来源 CIDR 和管理员凭据后检查 SQLite 就绪状态。Sidecar 的 `GET /ping` 返回存活信号，`GET /health` 返回硬件负载与卷状态。两者都需要该节点的 Bearer 凭据；启用 Hub 回查的节点还会检查凭据是否已撤销。

## 认证与撤销

PWA 会话使用随机 Cookie、HttpOnly、SameSite=Strict、服务端到期时间和注销失效。HTTPS 部署设置 Secure。Hub 对跨源浏览器写操作执行来源检查。CLI 使用独立的 Bearer API Key。配对码单次消费、有效期默认十分钟，数据库只保留其摘要。配对生成的 Sidecar 在处理每个认证请求时向 Hub 回查。撤销后 Hub 不再路由，节点拒绝旧凭据；正在执行的本机操作可能已产生效果，移除前应先检查并中止活跃任务。

Node Secret 只在配对响应中返回。手工种子节点要启用同样的在线吊销路径，须在节点私有配置同时给出对应的 node_id 和 hub_url。设备删除不会删除挂载卷文件。Hub 管理口令代表站点管理员，团队成员如共用该口令会共享管理权限。

## 文件、回调与诊断

Sidecar 私有 YAML 中的 `volume_roots` 定义管理员允许通过 UI 注册的存储区域。每项给出本机绝对 `path` 和 `read_only`。先在本机确认实际盘符与账户权限，再登记它所属的根。手机注册、更换或解绑的卷须落在已授权区域内，界面不能把管理员限定为只读的区域升级成可写。更换 NAS 映射盘符前，应先在本机加入新盘对应的授权根。书签的 DSM URL 与卷路径可分别修改。

- 卷 API 使用相对路径，检查越界、Windows 驱动器前缀、重解析点和只读策略。普通上传暂存后原子替换。任务产物转存采用独占创建，目标同名返回 409。目标 Sidecar 需支持 `upload_create_only`。Markdown 以受限元素渲染，CSV 有行列上限，SVG 在节点剔除活动内容后才可预览。
- 工作区文件快照保存在节点私有产物目录中；它作为只读卷供已认证客户端访问。按节点用户隔离备份和访问权限。保留或清理快照时同步考虑历史任务对文件的引用。
- 用名为 `file_hook` 的私有配置给出 JSONL 路径，或通过 `webhook` 和可选 `webhook_token` 指定 HTTP 接收端。通知按写入事件顺序投递，失败后重试；重复通知以事件 ID 去重。飞书卡片点击动作应重新查询审批状态，验证飞书操作者身份，提交指定审批 ID。
- `deploy/doctor.py --config FILE` 在对应机器运行，报告监听地址、端口、认证、节点 RTT、挂载卷和服务入口。服务端 RTT 包含 HTTP 处理时间；WOL 发送记录与实际开机状态分别报告。
- `deploy/remote-deploy-ssh.ps1 -Target ALIAS -DryRun` 可预演发布，实际分发前核实目标主机的 SSH 主机密钥。新发布目录中的安装器需要以服务所属用户启动。
## 从手机进入某台主机的 DSH

在 Fleet 的「设备」页打开节点卡片上的「DSH 工作台」。其中「向本机派单」会选中当前设备，「桌面共享会话」列出由该机桌面插件同步的会话，「Fleet 任务」可查看该机每项任务的工具输出和产物。

要使用 DSH 原生浏览器界面的聊天、历史、工具和设置，需要该主机安装包含 Web profile 的 DSH，并自行运行 Web 服务。先在该机运行 `dsh web --help` 核对版本。以下示例供具备相应证书的主机使用，请把尖括号替换为本机配置值。

```text
dsh --profile web --no-open --host <本机内网IP> --port <端口> --tls-cert <证书链文件> --tls-key <私钥文件>
```

1. 在节点编辑框选择 DSH Web 实际协议和端口。Fleet 从该节点的 Sidecar 地址取主机名生成入口。支持私有 IPv4、Tailscale 地址、IPv6 ULA、内网短主机名及 `.ts.net`、`.local`、`.lan`、`.internal`、`.home.arpa` 域名。手机须能解析并路由到该主机。使用 HTTPS 时证书应匹配手机使用的名称。
2. 若 Sidecar 地址采用 Tailscale 完整域名，请把 DSH 的 `--host` 设成本机 Tailscale IP，并用 `--public-url https://<节点域名>:<端口>/` 和 `--trusted-host <节点域名>:<端口>` 指定入口。若使用加密内网承载 HTTP，请在命令与 Fleet 中选择同一协议。只开放所需来源。
3. 在自己的手机浏览器私下打开 **DSH Web 启动时输出的完整链接** 以登录。经核对的 DSH 版本用根路径的 `?token=…` 换取签名 HttpOnly 会话 Cookie，然后跳转至无参数的根地址。此链接包含访问凭据。Fleet 节点设置仅接受协议与端口；手机应用内外若使用不同浏览器数据存储，需在实际打开 Web 的浏览器内完成这一步。
4. 回到「DSH 工作台」点「打开 DSH Web」，即可进入同一主机的浏览器会话。节点改址或 Cookie 到期后，用该 Web 进程输出的对应地址重新验证。请为 Hub 与 DSH Web 使用不同主机名，浏览器 Cookie 跨同一主机的端口发送。

DSH Web 使用其 Web profile 的会话存储、模型、工具和审批。Electron 窗口、托盘以及仅在桌面 profile 加载的插件由桌面应用负责。Fleet 的 Sidecar 任务遵循节点策略；Web 中发起的对话遵循 DSH Web 自身配置。
