# 发布验收记录

## 0.2.1 Windows 引导

Windows 全量 pytest 通过 104 项，包含 7 项 Windows PowerShell 5.1 引导回归。测试对临时 NTFS 文件和目录实际设置 DACL，核对当前用户和 SYSTEM 的访问权限以及原所有者和组。测试启动器驱动写入标准错误的子进程，验证正常退出和非零退出码均能传回调用者。

回环 HTTP 服务实际返回 403 和 429，覆盖 WinGet 可用及失败后从本地 wheel 通过 pip 安装两条路径。缺少摘要的成功响应也有独立测试。唯一警告来自 Starlette TestClient 的上游弃用提示。

节点配对与编辑共用端点 URL 校验函数。回归用例覆盖两个 Pydantic 模型，确保校验上下文和 URL 参数按预期传递。

## 0.2.0 核心功能

本轮在 Windows 上执行生产构建、真实子进程与浏览器验收。全量 `uv run --locked pytest -q -ra` 实测 **63 项通过，0 项跳过，耗时 84.60 秒**。Starlette 的 TestClient 报告一条上游弃用提示。集群、模型端点、飞书协议接收器均使用临时数据。其他设备缺少 DSH 或桌面运行时时，相应测试会报告跳过。

## 桌面续聊与设备拓扑

此次 Windows 全量回归为 94 项通过，另有一条 Starlette TestClient 依赖弃用提示。真实 Electron 桌面组件将任务写入隔离的工作区，宿主重启后可在原生会话列表查到同一 ID。分别用两版官方 SDK 恢复该 ID 并追问，本地模型端点收到了前一轮工具返回的随机内容和新问题，历史工具调用次数保持不变。另验证重复交接、无效凭据及不支持的历史格式。

390 × 844、两倍像素密度的 Playwright 验收使用三台回环 Sidecar。实际派单回执和审批事件分别触发下发、回传标记；不同主机的工作台各自显示其任务。核对了触控目标、横向溢出、浏览器异常和离线壳。DSH Web 使用独立临时 profile 验证启动链接换取登录 Cookie 的流程。[演示设备拓扑](images/fleet-zh.png)

拓扑复验在页面打开期间通过配对接口加入第四个回环测试节点。浏览器观测到节点自动出现，探活成功后虚线开始流动，停用后静止，移除后分支消失。390 × 844 和 1440 × 900 两种视口均核对了箭头与新卡片的连接位置，并按浏览器动画的实际位移验证下发、回传方向相反。系统开启「减少动态效果」时，两条虚线均保持静止。

## 复验

在仓库根目录运行以下命令。Playwright 使用已安装的 Chromium 或 Chrome。截图中会话路径和临时配对凭据已遮盖。留存 19 张移动截图与 1 张桌面截图，并目视检查了审批横幅、触控按钮、换行文件名、表格和图像放大层。[公开示例截图](images/)

```sh
uv lock --check
uv run --locked pytest -q -ra
uv run --locked python tests/ui/run.py
uv run --locked python deploy/privacy_check.py
```

实机 NAS、远端 Hermes、生产飞书租户、付费模型及 Linux/macOS 上的服务安装需在目标环境验证。自定义群机器人分别发送待审批卡和结果卡，自建应用可更新原卡。网络中断期间以 Hub 的审批记录和执行端最终回执为准。单活 Hub 支持在原数据库恢复；宿主机故障恢复需要备份或备用主机。
